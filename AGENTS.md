# ResearchRadar MAS — постоянные правила проекта

Перед изменениями прочитать `project_guide/Лабораторные-МАС.pdf`, `docs/architecture.md`, `docs/decisions.md`, `docs/progress.md`, `docs/handoff.md` и проверить Git. Методичка — основной источник требований четырёх лабораторных, лекции — вспомогательная теория. ЛР №1 и №2 выполнены по отдельным поручениям; ЛР №3–4 не начинать без нового поручения.

Проверка на Windows/Python 3.14: `py -3.14 -m unittest discover -s tests -v`; автономная демонстрация: `py -3.14 -m researchradar.cli "multi agent systems" --mode demo`. Сетевые и платные проверки проводить отдельно и экономно. Синтетические fixtures не выдавать за реальные источники. Ключ OpenRouter находится вне Git в `%LOCALAPPDATA%/ResearchRadar_MAS/.env`; никогда не печатать его. Журнал расходов SQLite также вне Git.

Все основные отчёты — самостоятельные научно-технические документы. В их заголовке и тексте нет обозначений лабораторных, этапов, учебных требований, методичек или преподавателя. Эти сведения размещаются только в комплекте сдачи, например `submission_manifest.md`. Автор: Коротаев Андрей Дмитриевич, группа Б24-507. Преподавателя не указывать. Не добавлять неподтверждённое название организации. Не выдумывать результаты испытаний и не публиковать черновики как окончательные материалы.

Архитектурные схемы, графы коммуникаций, диаграммы переговоров, схемы отказов и количественные графики делать преимущественно векторными и визуально проверять до публикации. DOCX и PDF рендерить и осматривать постранично. Технический отчёт отделять от сопроводительных файлов сдачи и внутренних файлов управления разработкой. Сохранять исходники схем, историю Git и доказательства работоспособности.

После значимых решений обновлять `docs/decisions.md`, после проверок — `docs/test-status.md`, перед передачей задачи — `docs/progress.md` и `docs/handoff.md`. Статусы источников сверять с `docs/source_policy.md`, историю LIVE-проверок и расходов — с `docs/api_validation.md`. Для версии 1.2 архивы собирает `tools/package_submission.py`, для версии `lab2-v1.1` — `tools/package_lab2.py`; оба создают учебный и аудиторский ZIP с manifest и SHA-256. Эксперименты из архива проверять в отдельном каталоге вне Git, с импортом именно распакованной копии; новые запуски писать в `run_output/`, не в сохранённый корпус `experiments/results/`. До публикации проверять тесты, PDF/DOCX, секреты, GitHub Actions и состав релиза. Старые опубликованные теги и релизы не переписывать; force push не использовать.
