# Проверка внешних API и расходов

Проверки ниже выполнены для версии 1.1 на Windows 11 и Python 3.14. Для редакции 1.2 повторные платные вызовы и бессмысленные запросы к ограниченному GDELT не выполнялись.

| Проверка | Наблюдение | Интерпретация |
| --- | --- | --- |
| OpenAlex LIVE | Три научные записи по теме `artificial intelligence` | Работоспособность адаптера подтверждена в проверенной среде; содержание работ не верифицировано. |
| GDELT LIVE | HTTP 429 на одном аккуратном запросе | Отказ обработан; получение данных этим адаптером в проверенной среде не подтверждено. |
| Google News RSS LIVE | Три новостные записи по той же теме при явном `--news-source rss` | Подтверждён отдельный резервный агрегатор, а не GDELT. |
| Qwen через OpenRouter | Отдельный вызов дал ответ; 16 входных и 154 выходных токена; `usage.cost` = 0,0001564 USD | Клиент доступен; он не входит в обязательный сквозной цикл. |

Ранее подтверждены ещё два вызова OpenRouter на 0,0002548 USD. Сумма **известных подтверждённых расходов** — 0,0004112 USD. Один более ранний короткий вызов завершился без сохранённого `usage`; его фактическая стоимость неизвестна. Поэтому 0,0004112 USD нельзя считать полным расходом аккаунта.

После этого клиент переведён на постоянный SQLite-журнал вне репозитория. Он записывает `pending` до сетевой отправки, резервирует оценочную стоимость, сохраняет ID провайдера, токены и фактическую цену после ответа. При таймауте расход отмечается как неопределённый и повтор автоматически не выполняется. Для успешного ответа без `usage.cost` оценка остаётся в бюджете. Идентификатор `call_id` уникален, повторная отправка с тем же ID запрещена. Обычный CLI и автоматические тесты не обращаются к OpenRouter.

Воспроизведение без расходов: `py -3.14 -m unittest discover -s tests -v` и `py -3.14 -m researchradar.cli "multi agent systems" --mode demo`. Сетевой поиск через RSS запускается отдельно: `py -3.14 -m researchradar.cli "artificial intelligence" --mode live --news-source rss`. Для платного вызова требуется явная проверка актуальных тарифов и отдельный локальный ключ в `%LOCALAPPDATA%/ResearchRadar_MAS/.env`; журнал находится в `%LOCALAPPDATA%/ResearchRadar_MAS/usage.sqlite3` и не входит в архивы.

## Проверка этапа 2 — 30 октября 2026

Команда `py -3.14 -m researchradar.cli_stage2 "multi agent systems" --mode live --coordination contract-net` вернула по три записи OpenAlex, Crossref, arXiv и Google News RSS; все четыре задачи завершились. Отдельный запуск с `--llm live` сформировал альтернативный запрос `applications and architectures of multi-agent systems in AI`, добавил пятую научную подзадачу и завершил 5/5 задач. Обобщённое свидетельство без полных записей и секретов — `audit_evidence/stage2_live_summary.json`. GDELT повторно не опрашивался и по-прежнему не объявляется успешно проверенным.

Для содержательной функции Qwen выполнены **два новых вызова** через бюджетируемый клиент. Первый завершился пустым пользовательским текстом после 56 входных и 256 выходных токенов; `usage.cost` = 0,0002644 USD. После установки `reasoning_effort=none` второй вызов вернул структурированный поисковый запрос: 58 входных и 21 выходной токен, `usage.cost` = 0,0000297 USD. Подтверждённые расходы этапа 2 — **0,0002941 USD**. Вместе с ранее подтверждёнными 0,0004112 USD известная сумма составляет **0,0007053 USD**; она не является абсолютным расходом аккаунта из-за одного старого вызова с неизвестной ценой. В текущем SQLite-журнале есть три вызова на 0,0004505 USD: старый успешный smoke test и два новых; ещё два исторических подтверждённых вызова учтены в документации, а не в этой базе.

Перед LIVE-вызовами проверена [страница модели OpenRouter](https://openrouter.ai/qwen/qwen3.5-35b-a3b) с заявленной базовой ценой 0,08/0,75 USD за миллион входных/выходных токенов и различием цен провайдеров. Для локальной предварительной оценки переданы консервативные 0,5/3 USD за миллион. `max_tokens` ограничен 512, а существующий локальный бюджет — 8 USD с лимитом 0,05 USD на отдельный вызов. Воспроизведение интеллектуального плана без оплаты: `--llm recorded --recorded-plan data/recorded_plan.json`; этот план не изменяется между сравниваемыми механизмами.
