# Модель угроз и протокол исходного обследования

## Вопрос и границы

Исследование проверяет, как неблагоприятные сообщения, неисправные источники и искажённая локальная цель влияют на корректность и доступность ResearchRadar MAS. Историческая точка сравнения — неизменённый исходный код тега `lab3-v1.1`, сохранённый в `experiments/lab4/baseline_lab3_v1.1.zip`; его SHA-256 `da223cc3ff29e0a0842c159270c4697ca3d5960d0359e6388119de8f56caaa2a`. Это исполняемый снимок для стенда, не второй рабочий проект.

Защищаемые свойства: принадлежность сообщения текущему исследованию и заданию, целостность найденных материалов и их происхождения, корректное завершение части исследования при отказе источника, полномочия участников, атомарные кредиты и слоты, ограничение затрат OpenRouter и доказательность интеллектуального вывода. Внешние API, их текстовые поля, ответы Qwen и неисправные агенты рассматриваются как недоверенные. Координатор, посредник и код ресурсного журнала считаются доверенной логикой внутри одного Python-процесса. Строка `sender` не является криптографической аутентификацией; захват процесса или доступ к его памяти вне модели защиты.

Воздействия вводятся в действующие интерфейсы: `Bus.send`, `Worker.score`, `Source.search`, `VerificationBudget` и отдельный анализ недоверенного материала. Стенд не обращается к реальным API и не читает ключ. Воспроизведение не требует Git: снимок исходной версии включён в архив. Каждый запуск сохраняет фактическую трассу шины, тип воздействия, результат и метрики.

## Зафиксированное поведение lab3-v1.1 до новых защит

| Воздействие | Наблюдение исходной версии | Оценка |
|---|---|---|
| Ответ с чужим `request_id`, но верной корреляцией | Внедрённый материал принят | нарушение принадлежности исследования |
| Результат с неполной структурой материала | `TypeError` прервал всё исследование | потеря доступности |
| Новостной материал как результат научной задачи | Принят; научных материалов 2 вместо 3, новостей 2 вместо 1 | нарушение типа и происхождения |
| `shutdown` с чужим `request_id` | Исполнитель прекратил работу; понадобилось повторное назначение | лишняя задержка и зависимость от резервного исполнителя |
| Отрицательная ставка изменившего цель агента | Агент выиграл научную задачу | нарушение допустимого диапазона заявки |
| Отказ arXiv с имитацией HTTP 429 | Остальные три задачи завершились, ошибка arXiv указана | существующая деградация работает |
| Ответ с неверной корреляцией | Отклонён; обычная задача завершилась | существующая защита работает |
| Делегирование worker→worker | Запрещено маршрутизатором | существующая защита работает |
| Попытка чужого владельца завершить договор | Отклонена журналом, собственное завершение прошло | существующая защита работает |

Числа выше относятся к первой контролируемой пробе с seed 0; основные парные испытания используют одинаковые сценарии и несколько seed. Не всякое изменение — нарушение безопасности: недоступный arXiv ведёт к частичному результату, а правильное отклонение сообщения считается успехом исходной системы.

Гипотезы защиты: строгая проверка `request_id`, корреляции и типа результата устранит принятие внедрённых материалов и локализует ошибку структуры; проверка допустимой числовой ставки ограничит изменённую локальную цель; ранняя проверка принадлежности `shutdown` устранит ложное выключение. Проверки нормального сценария и ложных срабатываний обязательны. Накладные расходы измеряются отдельно по времени, числу сообщений и повторным назначениям. Истинность содержательных оценок агента из одного сообщения доказать нельзя; полномочия `sender` без отдельной аутентификации остаются ограничением.
