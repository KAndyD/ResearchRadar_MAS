# Жизненный цикл бюджета проверок — lab3-v1.1

`VerificationBudget` учитывает две независимые величины. `credits` — накопительный предел стоимости проверок; `spent + held <= credits`. `concurrent_slots` — число проверок, исполняемых одновременно; `active <= concurrent_slots`. Одна полная проверка стоимостью два кредита занимает один слот. `peak_active` и `snapshot.active` всегда измеряют количество проверок, а не кредиты. Параметр `--slots` в CLI и необязательный `concurrent_slots` в `review_research` задают это ограничение независимо от `credits`; старые вызовы сохраняют прежние значения по умолчанию.

| Фаза | Кредиты | Слот | Допустимые переходы |
|---|---|---|---|
| `reserved` | в `held` | свободен | `start → active`, `cancel/abort → cancelled` |
| `active` | в `held` | занят | `finish → finished`, `abort → failed` |
| `finished` | в `spent` | свободен | терминальная |
| `failed` | в `spent` | свободен | терминальная |
| `cancelled` | возвращены | свободен | терминальная |

Все переходы и проверка свободного слота выполняются под одним `asyncio.Lock`. При одновременном `finish()` и `abort()` успешен только один переход; стоимость уже начатой проверки учитывается ровно один раз. Повторный переход возвращает `False`. Владелец и идентификатор заявки проверяются при резервировании и авторизации; операции с чужим договором не изменяют его.

Когда `start()` возвращает `False`, агент завершает попытку контролируемым отказом без ожидания, вызывает `cancel()` для ещё не начатого договора и отправляет `failure` с краткой причиной `start_denied`. Посредник вызывает `abort()` при полученном `failure` или отсутствии ответа; повторная очистка безопасна. Если операция была начата и затем завершилась ошибкой либо истёк срок ожидания, `abort()` переводит её в `failed`, освобождает слот и учитывает кредиты как `spent`. Агент отправляет `result` только после успешного `finish()`; посредник принимает его только при фазе `finished`. Поздний результат после таймаута в текущий итог не включается.

Политика без ожидания выбрана для короткой проверки и ограниченного времени посредника. Она допускает отказ при кратковременной занятости слота; повторное назначение потребовало бы нового соглашения и сейчас автоматически не выполняется. Переговорные оценки, уступки, арбитраж и правила распределения кредитов не менялись.

Проверка: `py -3.14 -m unittest discover -s tests -p test_stage3_resource_regression.py -q`; полный протокол с одним слотом: `py -3.14 -m researchradar.cli_stage3 "multi agent systems" --mode demo --resource-policy baseline --credits 4 --slots 1 --output run_output/slot_conflict.json`. Ожидаются один завершённый двухкредитный договор, один `failure`, `spent=2`, `held=0`, `active=0`, `peak_active=1`. Результаты оригинального эксперимента в `experiments/lab3/results/` сохраняются отдельно.
