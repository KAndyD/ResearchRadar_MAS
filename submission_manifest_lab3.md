# Сопроводительная сверка лабораторной работы №3

Нормативный источник — `project_guide/Лабораторные-МАС.pdf`, раздел «Проектирование механизма переговоров и разрешения конфликтов». Лекции в рабочей директории не найдены. Основной отчёт `ResearchRadar_MAS_Resource_Negotiation` оформлен как самостоятельное исследование; учебная сверка вынесена сюда.

| Требование методички | Реализация и свидетельство |
|---|---|
| Смоделировать конфликт интересов и дефицит ресурса | Научный, новостной и сопоставляющий проверяющие агенты предъявляют несовместимые заявки на целочисленный бюджет углублённой проверки. Каждая полная проверка требует два кредита, частичная — один. При бюджетах два и три из шести запрошенных единиц все цели одновременно недостижимы. `src/researchradar/negotiation.py`, `resources.py`, `experiments/lab3/scenarios.json`. |
| Реализовать способ переговоров и разрешения конфликта | Два раунда сообщений `request/offer/counter/accept/reject`, самостоятельная уступка агента, подтверждение соглашения, ограниченный арбитраж при молчании. Протокол, корреляция и трасса реализованы явно без MAS-фреймворка и без LLM-решения. `docs/diagrams/lab3_protocol.svg`, `tests/test_stage3.py`. |
| Сравнить поведение до и после | Корректная FIFO-политика baseline и переговоры используют одни и те же материалы, заявки, предварительные оценки, seed и ресурс. Пять сценариев × 12 пар = 120 запусков. `tools/run_negotiation_experiments.py`, `experiments/lab3/results/raw.csv`, `inputs.json`, `summary.json`, `paired.json`. |
| Оценить эффективность, справедливость, общие ограничения | Полезность — сумма предварительных оценок выполненных проверок. Справедливость — индекс Джейна по доле удовлетворённой индивидуальной полной потребности. Сообщения и время измерены в реальном протоколе. Превышения бюджета и активных слотов автоматически проверяются в каждом прогоне; сохранённые 120 запусков дали ноль таких нарушений. `tools/verify_lab3_results.py`, четыре SVG-графика. |
| Представить результаты и выводы в отдельном отчёте | `deliverables/ResearchRadar_MAS_Resource_Negotiation.docx` и `.pdf`; 7 страниц, две архитектурные схемы, четыре графика и таблица рассчитанных результатов. |

## Воспроизведение

На Windows 11 с Python 3.14 из корня распакованного ZIP: `py -3.14 -m pip install -e .`, `py -3.14 -m unittest discover -s tests -q`, затем `py -3.14 tools/run_negotiation_experiments.py --repeats 1 --output run_output/lab3_smoke` и `py -3.14 tools/verify_lab3_results.py --results run_output/lab3_smoke`. Git, сеть и OpenRouter для этих команд не требуются. Отдельный интеграционный тест копирует код во внешний временный каталог, убирает Git из PATH и проверяет, что импортируется именно эта копия.

Возможность показать конфликт: `py -3.14 -m researchradar.cli_stage3 "multi agent systems" --mode demo --resource-policy baseline --credits 3`, затем та же команда с `--resource-policy negotiation`. Изменённые allocations, результаты проверок и трассы будут в `run_output/stage3-result.json` (для сохранения обоих результатов укажите разные `--output`). `--allocation centralized|contract-net` проверяет совместимость с прежними механизмами выбора поисковых исполнителей.

## Границы интерпретации

Исходные материалы сравнительного стенда явно синтетические. Полезность выражает модельную предварительную оценку, а не истинность научной статьи или новости. Нормированная равномерность распределения не заменяет обсуждение разных приоритетов. Тематическая связь помечается кандидатом, новостное утверждение без полного текста остаётся непроверенным. Времена зависят от планировщика ОС, а два раунда и одна заявка на роль ограничивают обобщение результатов. Ресурсный кредит — модельное ограничение исследовательской работы, не деньги OpenRouter. В LIVE-проверке использовался сохранённый ответ Qwen; новых платных запросов не было.
